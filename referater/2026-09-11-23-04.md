# Referat 2026-09-11

## Hvad blev lavet

### M4 — testmiljøet deployet til k3s

`https://loft.test.gihc.online` kører nu: ingress-nginx → `loft-web` (nginx,
`config.js` fra ConfigMap) og `/v1` + `/healthz` → `loft-api`, postgres med PVC,
og coturn på host-nettet. Rækkefølgen: A-record via
`scripts/create-dns-record.sh` → `loft-secrets` (password genereret og gemt i
`pass` som `loft/postgres-password`) → `kubectl apply -f k8s/test/` →
cert staging → verificér → prod-issuer → smoke-test → e2e.

To ting blokerede og blev løst undervejs:

- **`trunk` havde intet `.github/workflows/`.** GitHub Actions viser og
  dispatcher kun workflows fra default branch, så `loft`/`loft-web` var aldrig
  bygget (anonym pull gav 403). `workflow_dispatch` blev tilføjet, grenen
  merget til trunk (fast-forward), og CI byggede begge images med SHA-tags.
- **`GET /healthz` var ikke nåbar udefra**, fordi ingressen kun rutede `/v1` og
  `/`. Der er nu en eksplicit `/healthz`-rute til API'et.

### E2e-jobbet i CI var også i stykker

Workflowet satte `BASE_URL`, hvilket slår `playwright.config.ts`' indbyggede
statiske server fra — testene ville ramme en tom port 8888. Rettet (BASE_URL
sættes nu kun når man tester et deployet miljø).

### coturn: hærdning, misbrugsbeskyttelse og en lærerig fejl

Første forsøg på hardening (`allowPrivilegeEscalation: false` +
`capabilities.drop: ["ALL"]`) gav `CrashLoopBackOff` med
`exec /usr/bin/turnserver: Operation not permitted`. Kontrollerede forsøg som
engangspods på loft-test isolerede årsagen:

| securityContext | Resultat |
|---|---|
| `allowPrivilegeEscalation: false` | Running (NoNewPrivs=1) |
| `drop: ["ALL"]` | EPERM ved exec |
| begge | EPERM (som i deploymentet) |
| `drop: ["ALL"]` + `add: ["NET_BIND_SERVICE"]` | Running |
| + `allowPrivilegeEscalation: false` | Running (CapEff=0) |
| + `runAsNonRoot` (65534) | Running (CapEff=0) |

Årsagen er at `/usr/bin/turnserver` bærer **file-capabilities**. Tømmes
bounding-settet, nægter kernelen `execve` af binæren — bevist ved at en **kopi**
af samme fil (uden xattr) kører fint. Med `add: ["NET_BIND_SERVICE"]` lykkes
exec, men `no_new_privs` forhindrer at capabilityen gives videre til processen.
Min første forklaring (at `no_new_privs` blokerede exec) var altså forkert.

Endelig konfiguration: `runAsUser: 65534`, `runAsNonRoot`,
`readOnlyRootFilesystem`, `allowPrivilegeEscalation: false`, `drop: ["ALL"]` +
`add: ["NET_BIND_SERVICE"]`. Hertil misbrugsbeskyttelse, fordi `TURN_SECRET`
ligger offentligt i `config.js`: `--denied-peer-ip` for
RFC1918/loopback/link-local/CGNAT/IPv6, `--max-bps=2000000`,
`--bps-capacity=50000000`, `--user-quota=8`, `--total-quota=40`,
`--stale-nonce=600`. `-n` er droppet, fordi imagets entrypoint kører
`eval "echo $i"` og gør `echo -n` til et tomt argument.

### Ny TURN-relay-test

`e2e/tests/turn.spec.ts` (kørbar med `npm run test:turn`) tvinger
`iceTransportPolicy: 'relay'` i to selvstændige browser-kontekster og kræver
relay-kandidater i begge ender plus data begge veje. Den er den eneste test der
faktisk rører coturn — STUN-only-tests forbinder direkte. Kørt grøn mod
`loft.test.gihc.online` sammen med de fire loft-tests (5/5).

## Beslutninger

- **M0–M3 merges til `trunk`** — nødvendigt for at CI overhovedet ser
  workflowet, og grenen var en ren fast-forward.
- **TURN_SECRET bliver i ConfigMap'en.** Den er reelt offentlig (den udleveres
  til browseren), så kvoter og `--denied-peer-ip` er modvægten. Langsigtet
  løsning ligger i TODO: udsted credentials i API'et med kort TTL.
- **`NET_BIND_SERVICE` i bounding-settet er en bevidst undtagelse** fra
  "drop alt", dokumenteret i manifestet med begrundelsen.
- **Prod-manifesterne forberedes, men deployes først efter manuel accepttest**
  af testmiljøet med rigtige enheder.

## Gotchas

- GitHub Actions læser kun workflows fra **default branch**; `push`-triggere
  bruger derimod workflow-filen fra den gren der pushes.
- File-capabilities + tomt bounding-set → `execve` fejler med EPERM. Gælder
  også andre images (fx `ping` i hårdt lockdownde containere).
- Imagets entrypoint spiser `-n` (bliver til tomt argument → "Unknown argument").
- Browserens ICE-stak bruger **ikke** `--host-resolver-rules`; mangler
  navneopslag, så kør relay-testen med TURN på IP.
- systemd-resolved cacher NXDOMAIN i SOA-minimum: `sudo resolvectl flush-caches`
  efter en ny record.
- SSH til VPS'en kræver den oplåste nøgle i GNOME-keyring-agenten
  (`SSH_AUTH_SOCK=/run/user/1000/gcr/ssh`); med tom agent fejler `BatchMode`.
- Docker/podman kan ikke køre i sandkassen (`/run/user/1000` er read-only) —
  lokale containere kræver eskaleret kørsel.
- `.guidelines/` findes ikke i denne klon, så `scripts/check.sh` springer det
  semantiske review over.
